Tecnologías de Web APIs

Las APIs son el lenguaje invisible que permite que las aplicaciones se hablen entre sí, evitando que tengas que reinventar la rueda en cada proyecto. Imagina poder integrar la potencia de los mapas de Google o la seguridad de cobros de PayPal en tu propia aplicación con solo unas líneas de código.

Palabras clave:

REST GraphQL SOAP WebSockets

¿Qué es una Web API?

Una Web API (Application Programming Interface) es un conjunto de reglas y protocolos que permiten que dos aplicaciones o sistemas de software se comuniquen entre sí a través de internet. Actúa como un intermediario que recibe solicitudes, las procesa y devuelve respuestas estructuradas.

Funciona como una capa de abstracción, permitiéndote interactuar con funciones complejas sin necesidad de saber qué pasa técnicamente por debajo, es decir que permite que las empresas compartan funcionalidades de manera controlada y eficiente con el resto del mundo.
Actúa como un contrato: el cliente solicita algo y la API entrega los datos necesarios siguiendo un protocolo estándar.

REST (Representational State Transfer)

El estilo arquitectónico más popular. Usa los verbos HTTP de forma semántica:

  • GET — Obtener recursos
  • POST — Crear recursos
  • PUT / PATCH — Actualizar recursos
  • DELETE — Eliminar recursos

Utiliza principalmente el formato JSON, que es mucho más ligero y fácil de leer para los humanos y las máquinas. Se basa en una comunicación "sin estado", lo que significa que cada petición del cliente al servidor debe contener toda la información necesaria para entenderse, lo que permite que las aplicaciones sean increíblemente rápidas y escalables en entornos de microservicios.

SOAP (Simple Object Access Protocol)

Protocolo basado en XML, estándar en entornos empresariales y sistemas legados. Características:

  • Utiliza sobre de XML estructurado (Envelope)
  • WSDL para describir el servicio
  • Mayor seguridad y soporte transaccional (WS-Security)
  • Protocolo independiente (HTTP, SMTP, etc.)
  • Verboso pero altamente estandarizado

    • Es conocido por su robustez y su capacidad para manejar operaciones complejas que requieren una seguridad extrema y transacciones garantizadas. Se utilizapara sistemas bancarios, financieros y servicios gubernamentales donde la integridad de los datos no es negociable.

HTTP y HTTPS

Para que una API funcione, necesita un camino por donde viajar: ese camino es el protocolo HTTP (HyperText Transfer Protocol)

Es el sistema de reglas que permite la transferencia de información en la web.
Sin embargo, para proteger datos sensibles como contraseñas o tokens, se utiliza HTTPS, que es la versión segura de HTTP. Esta "S" adicional significa que toda la comunicación está cifrada mediante certificados SSL/TLS, garantizando que nadie pueda interceptar o leer los mensajes mientras viajan por la red.

GraphQL

Desarrollado por Facebook en 2015 como alternativa a REST. Sus ventajas principales son:

  • El cliente solicita exactamente los datos que necesita
  • Un único endpoint para todas las operaciones
  • Evita el over-fetching y el under-fetching
  • Sistema de tipos fuertemente definido (Schema)
  • Permite suscripciones en tiempo real

El uso principal de esto son redes sociales complejas, aplicaciones con muchos datos interconectados y plataformas que necesitan optimizar al máximo el rendimiento.

WebSockets & gRPC

A diferencia del HTTP tradicional (donde el cliente pregunta y el servidor responde), los WebSockets permiten una conexión bidireccional y persistente.
Se establece un "apretón de manos" (Handshake) inicial y, una vez aceptado, el canal queda abierto permanentemente. Ambos pueden enviarse datos en cualquier momento sin necesidad de nuevas peticiones.
Es la tecnología detrás de los chats en vivo, las notificaciones instantáneas y los juegos online. Si ves que el precio del Bitcoin cambia en tu pantalla sin que refresques la página, estás viendo WebSockets en acción.
Este tipo de tecnologias se utilizan en apps financieras, herramientas colaborativas (como Google Docs) y tableros de control (dashboards) en vivo.
